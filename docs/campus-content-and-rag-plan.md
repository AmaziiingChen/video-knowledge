# 校园内容接入与跨文章问答方案

日期：2026-07-15

## 结论

当前项目已经具备统一内容实体、正文缓存、全文索引、单篇 AI 分析、问答、Markdown 与 Obsidian 同步。校园场景不需要另建一套阅读器；应把学院官网和公文通作为新的文章来源接入现有链路。

本轮先落地校园来源的“显式同步 → 去重入库 → 按需抓正文 → 阅读/分析/问答”。定时调度、校园来源管理 UI 和跨文章 RAG 分阶段推进。

公文通增加校内直连与校外 WebVPN 双通道：桌面端以独立 Chromium 分区承载学校登录页和会话，后端永远不接收统一认证账号、密码、验证码或 Cookie。校外首次登录后，用户从 WebVPN 服务大厅打开一次公文通，应用记录代理入口；后续同步在直连不可用时通过该会话抓取列表和正文，并将脱敏后的文章快照写入通用缓存。

## 从 BestBlogs 借鉴什么

BestBlogs 的公开仓库没有开放 Copilot 后端的完整实现，但公开文档和 Dify 工作流已经给出足够清晰的边界：

1. 单篇长文先处理。超过约 6000 字符时分段分析，再聚合成单篇结构化结果。
2. 结构化结果是长期资产。摘要、关键观点、标签、评分等先入公共质量池，而不是每次跨文章问答都重读全部原文。
3. 跨文章能力建立在搜索读模型上。公开架构把 Elasticsearch 定义为搜索、相似内容和向量召回的承接位。
4. “主题解读”负责组织多篇碎片。它不是把每日列表机械拼接，而是把相关文章、视频、播客和推文组织成可追踪的主题页面。
5. 权限、内容可见性和成本治理位于服务层，不能由前端临时拼上下文绕开。

## 从 MicroFlow 借鉴什么

### 校园来源

MicroFlow 内置了公文通和学院官网的页面入口、异构列表选择器、日期清洗、正文容器与附件识别经验。本项目将这些经验整理为配置化来源注册，不复制 MicroFlow 的调度器、数据库和 UI 状态机，避免形成第二套内容系统。

当前注册来源：

- 公文通；
- 人工智能学院；
- 新材料与新能源学院；
- 中德智能制造学院；
- 城市交通与物流学院；
- 健康与环境工程学院；
- 工程物理学院；
- 药学院；
- 创意设计学院；
- 商学院；
- 集成电路与光电芯片学院；
- 未来技术学院；
- 外国语学院；
- 音乐学院。

### 详情交互

MicroFlow 的详情切换采用短时淡出、替换内容、再淡入，并为连续切换做了防抖。本项目先移植其中最稳定的视觉部分：以详情容器为单位的单次组合动画，不分别动画化每个卡片和按钮；同时尊重 `prefers-reduced-motion`。

## 当前校园 API

- `GET /api/campus-sources`：列出来源与板块。
- `POST /api/campus-sources/{source_slug}/sync`：抓取并去重写入内容库。

请求示例：

```json
{
  "section": "通知公告",
  "limit": 20
}
```

同步结果进入“校园官网 / 来源名称”文件夹。打开文章时按需抓正文；正文缓存后可以直接预览、全文检索、运行结构化分析或在右侧提问。

## RAG 分阶段方案

### 阶段 0：摘要优先的轻量跨文章问答

暂不引入向量数据库。先使用 SQLite FTS 召回候选文章，再按以下优先级组装上下文：

1. 单篇结构化摘要与关键观点；
2. 与问题命中的正文片段；
3. 标题、来源、发布时间和原链接；
4. 必要时补充相邻片段。

硬性预算：

- 候选文章默认 8 篇；
- 每篇最多 2 个正文片段；
- 同一来源不超过候选集的 50%；
- 至少保留 15% 上下文给回答指令与引用表；
- 每条结论必须返回 `content_item_id` 和原链接。

### 阶段 1：分块与分层压缩

新增 `content_chunks`，保存章节或滑窗分块及 FTS 文本；新增单篇 `document_brief`，保存摘要、实体、时间、行动项、关键断言和证据片段。长文采用：

```text
原文 → 语义分块 → 分块摘要 → 单篇汇总 → 可检索结构化资产
```

跨文章问答采用：

```text
问题 → FTS 召回文章 → FTS 召回片段 → 去重/多样性排序
     → 按 token 预算组装 → 带引用回答
```

### 阶段 2：混合召回

只有在 FTS 对同义表达、口语提问和跨模态文本的召回效果不足时，再为 `content_chunks` 增加 embedding。采用关键词分数、向量分数、时间新鲜度和来源多样性的混合排序，不把向量库作为新的事实主库。

## 下一步

1. 扩展现有校园设置页：按学院启停、选板块、显示各来源上次结果；当前已支持公文通连接、立即同步和本次同步结果。
2. 增加低频增量调度和失败退避，默认每个来源串行抓取，限制并发。
3. 为附件建立独立资产记录；公文通 PDF/Office 附件接入现有 OCR/文本抽取链路。
4. 落地 `content_chunks` 与 FTS 片段检索，再实现跨文章问答 API。
5. 用校园问题集评估召回率、引用正确率和“未找到证据时拒答”能力，达标后再考虑 embedding。
