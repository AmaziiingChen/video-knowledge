# KnowledgeHub 产品遥测与使用数据方案

版本：v1.0（方案）  
日期：2026-07-25  
状态：本机同意、队列和默认禁用的上传器已实现；Cloudflare 收集器待正式域名、数据处理方与部署授权确认

## 1. 决策摘要

KnowledgeHub 发布后应引入**隐私优先、用户可控、默认不开启上传**的产品遥测，用于判断产品是否稳定、用户在哪些链路受阻，以及哪些功能值得持续投入。遥测不是内容同步：视频、字幕、文章正文、问答、Markdown、截图、Cookie、令牌和文件路径均不进入遥测系统。

第一期不接入第三方行为分析 SDK。应用在本机先写入一个独立、可删除的遥测队列；只有用户主动允许“发送匿名使用数据”后，才通过 HTTPS 批量发送已脱敏事件到官方收集端。这样既保留本机优先的产品承诺，也能得到发布后最有价值的质量与使用信号。

当前代码已经实现固定事件目录、严格枚举、14 天/10,000 条本机队列上限、非模态说明、同意版本边界及低频批量上传器。上传器仅接受源码白名单中的精确 HTTPS 主机，禁用代理和重定向，失败时保留队列并指数退避。`telemetry-worker/` 提供 Cloudflare Worker + Workers Analytics Engine 的收集器源码，但正式主机白名单和收集地址仍为空，因此当前不会启动上传线程或发送任何请求。

## 2. 目标、非目标与成功标准

### 2.1 目标

1. 量化启动、导入、处理、搜索、问答、同步和报告等核心旅程的完成率与耗时。
2. 以稳定的错误类别和阶段定位可靠性问题，不上传原始报错或用户内容。
3. 识别功能采用率、漏斗流失和性能回归，为版本优先级提供证据。
4. 让用户随时知道是否在共享数据、将要共享什么，并能一键停止和清除。

### 2.2 非目标

- 不做广告、跨站追踪、用户画像、内容推荐画像或销售线索收集。
- 不记录页面键入、剪贴板、URL、搜索词、标题、文件名、公众号名称、账号标识、地理位置或设备硬件序列号。
- 不以遥测代替用户反馈、错误复现或安全日志。
- 不在未取得有效用户选择前向外网发送使用事件。

### 2.3 第一阶段成功标准

- 发布后可以按版本、macOS 大版本和处理来源类型，观察核心旅程的开始数、完成数、失败率和 P50/P95 耗时。
- 能在 24 小时内发现某版本的启动失败、任务失败或崩溃率显著回归。
- 用户可在设置页查看采集说明、上次发送时间、本地待发送数量，并可立即关闭和删除本地队列。
- 审计抽样确认：上报负载中不含正文、路径、URL、凭据、原始异常、用户输入或可逆个人标识。

## 3. 隐私与数据边界

### 3.1 许可模型

- **默认值：关闭。** 首次启动完成基本可用性引导后，以非打扰方式询问是否帮助改进产品；“暂不”与“允许”同等易选。
- 关闭时不创建可上传事件；仅保留产品运行必需的本地日志，且不把这些日志转作遥测。
- 开启后，可在“设置 → 隐私与诊断”随时关闭。关闭立即停止上传并删除本地待发送遥测；已经到达服务端的数据按既定保留周期去标识化保存，不能再关联到本机。
- 更新隐私说明、扩大字段或新增事件类别时，须提升遥测模式版本并重新征求同意，不得沿用旧同意。

### 3.2 允许字段

| 分类 | 允许的数据 | 约束 |
| --- | --- | --- |
| 版本与运行环境 | app 版本、构建号、发布渠道、macOS 主版本、CPU 架构、是否桌面包 | 不传设备名、用户名、主机名、精确系统补丁号 |
| 产品操作 | 固定事件名、功能模块、结果、来源类别、处理模式、是否使用缓存 | 均为预定义枚举；不得出现标题、URL 或用户自定义名称 |
| 性能 | 启动/阶段耗时、队列长度分桶、文件大小/时长分桶、内存压力等级 | 数值只服务于质量分析，不与内容关联 |
| 故障 | 错误类别、代码位置指纹、可否重试、发生阶段 | 禁止上传原始异常、堆栈、HTTP 响应、请求体和日志行 |
| 隐私控制 | 同意状态变更、队列被删除、上传是否成功 | 不记录同意页面中的其他交互 |

### 3.3 明确禁止字段

- 内容：视频/音频、图片、OCR 文本、字幕、文章、报告、Markdown、问答、提示词、搜索词和剪贴板文本。
- 身份与凭据：姓名、邮箱、手机号、IP 地址、设备标识符、Cookie、Token、API Key、登录态、微信/Telegram/Obsidian 账号。
- 可定位信息：文件路径、文件名、域名、完整 URL、外部来源 ID、网络 SSID、精确位置、时区以外的定位信息。
- 原始诊断：原始 error message、堆栈、HTTP headers/body、进程命令行、截图、日志片段。

## 4. 端到端架构

```text
Vue / Electron / FastAPI 产生预定义事件
                 ↓
         本地字段白名单与脱敏器
                 ↓
   独立 telemetry.sqlite 队列（可查看、可删除）
                 ↓  仅用户已同意、低频批量、HTTPS
        官方遥测收集 API（不接收自由文本）
                 ↓
  原始事件短期留存 → 聚合指标 / 版本健康仪表盘
```

### 4.1 客户端组件

1. **事件目录（event registry）**：代码中唯一允许出现的事件名、字段、枚举和版本。未知事件或未知字段直接拒绝写入。
2. **本地队列**：单独使用 `data/telemetry.sqlite`，不与 `app.db`、内容库或任务数据库混写；最多保留 10,000 条或 14 天，超过时先丢弃最早事件。
3. **上传器**：由后端在低优先级调度器中运行。启动后延迟、网络恢复后或每 12 小时最多发送一次；单次最多 100 条/256 KB，指数退避，不影响视频、ASR、OCR 或 AI 任务。收集地址为空时不创建网络请求。
4. **Electron 早期事件**：后端就绪前，主进程只把极少量启动/崩溃摘要写入受限 NDJSON 暂存文件；后端启动后导入独立队列。不能因遥测写入而阻塞窗口显示或应用退出。
5. **设置与审计 UI**：展示总开关、事件说明、上次上传结果、待发送数、服务地址、删除按钮和隐私说明版本。

### 4.2 建议的项目落点

| 位置 | 职责 |
| --- | --- |
| `backend/services/telemetry.py` | 字段校验、SQLite 队列、保留清理、批次构造与成功确认删除 |
| `backend/services/telemetry_uploader.py` | 精确目的地校验、低频上传、失败退避和应用生命周期 |
| `backend/routers/telemetry.py` | 仅本机可访问的设置、状态、事件写入、清除接口 |
| `backend/services/database.py` | 仅增加遥测设置迁移；事件队列使用独立数据库 |
| `backend/services/application_lifecycle.py` | 随桌面后端生命周期启动/停止上传器 |
| `backend/main.py` | 注册本机遥测路由并继承桌面 API 能力边界 |
| `frontend/src/services/telemetry.js` | 前端事件目录与调用门面；禁止业务组件直接网络上报 |
| `frontend/src/components/SettingsDialog.vue` | “隐私与诊断”设置页；沿用既有圆角 token 与设置页结构 |
| `frontend/electron/main.cjs` / `preload.cjs` | 主进程启动、渲染器失效和早期暂存；通过窄 IPC 暴露，禁止任意字段透传 |
| `tests/test_telemetry*.py` 与前端单元测试 | 字段白名单、关闭不写入、删除、上传重试、敏感字段回归测试 |

### 4.3 网络与服务端边界

- 客户端只允许连接构建时或签名远程配置中声明的官方 HTTPS 域名；开发环境可显式覆盖，正式包不接受任意用户输入的收集地址。
- 上传接口只接受严格 JSON schema，不接受自由文本字段、附件或任意嵌套对象；服务端也必须再次执行字段白名单验证。
- 不把用户配置的代理、第三方 AI Key 或内容来源会话用于遥测认证。
- 服务端必须限流、验证负载大小、记录 schema 拒绝率，并将管理端访问纳入最小权限控制。
- 选择托管分析产品前，必须完成数据处理协议、数据存储地域、删除能力、访问审计和字段禁令评估；第一期优先自建收集 API + 聚合库，避免 SDK 额外采集。

## 5. 事件契约

### 5.1 通用事件格式

```json
{
  "schema_version": 1,
  "event_id": "随机 UUID",
  "event_name": "pipeline_completed",
  "occurred_at": "2026-07-25T09:20:00Z",
  "installation_id": "本机随机 UUID，仅在本机 Keychain 保存",
  "session_id": "每次启动生成的随机 UUID",
  "app_version": "1.2.0",
  "build_channel": "stable",
  "platform": "macos",
  "os_major": 15,
  "architecture": "arm64",
  "properties": {
    "source_kind": "bilibili",
    "processing_mode": "full",
    "result": "succeeded",
    "total_duration_ms": 125000,
    "cache_hit": true
  }
}
```

`installation_id` 必须是首次选择加入时生成的随机值，不得由硬件、账号、网络或文件数据推导。它仅用于计算去重安装量与版本留存；用户关闭并清除遥测后应销毁该值，重新开启将生成新值。Cloudflare 收集器仅在内存中用其派生按月轮换的 HMAC 索引，不把原始 UUID 写入分析库。

所有 `properties` 都必须来自事件目录的枚举或数值范围。日期一律 UTC；时长以毫秒记录；文件大小、媒体时长和队列长度使用分桶值，例如 `0_1m`、`1_10m`、`10_60m`、`60m_plus`。

### 5.2 首个封闭测试版事件目录（严格 20 个）

| 事件 | 触发时机 | 允许属性 |
| --- | --- | --- |
| `app_started` | 已选择加入后的应用启动 | 无 |
| `workspace_opened` | 工作区切换/首次打开 | `view`（固定枚举） |
| `import_started` | 用户提交链接导入 | `input_kind`（当前仅 `link`） |
| `import_completed` | 链接已被本机接受并创建处理请求 | `result`（当前仅 `accepted`） |
| `task_enqueued` | 建立后台处理任务 | `processing_mode`（`full` / `transcript`） |
| `pipeline_stage_completed` | 处理阶段变更 | `stage`（固定阶段名） |
| `pipeline_stage_failed` | 任务失败时记录其最终阶段 | `stage`；不含错误文本 |
| `task_finished` | 任务最终成功或失败 | `result`、`stage`；不含错误文本 |
| `task_control_used` | 用户重试、暂停、恢复或取消任务 | `action`（固定枚举） |
| `paddle_ocr_completed` | 一次 Paddle OCR 云端结果返回 | `result`（`succeeded` / `empty` / `failed`） |
| `obsidian_sync_completed` | Obsidian 写入或冲突检测完成 | `result`（`succeeded` / `conflict`） |
| `search_completed` | 本地搜索完成 | `result_count_bucket`；不含搜索词 |
| `clipboard_listener_changed` | 剪贴板监听启用或停止 | `state`（`enabled` / `disabled`） |
| `update_check_completed` | 手动更新检查结束 | `result`（`available` / `up_to_date` / `disabled` / `unavailable`） |
| `telemetry_consent_changed` | 用户主动开启遥测 | `state`（当前仅 `enabled`；关闭会删除整个队列） |
| `update_download_page_opened` | 用户确认打开手动更新下载页 | 无 |
| `media_download_completed` | 媒体下载阶段结束 | `result`、`duration_bucket`；不含来源链接或文件名 |
| `asr_completed` | 转写阶段结束 | `backend`、`result`、`duration_bucket`；不含音频或文本 |
| `ai_summary_completed` | AI 总结阶段结束 | `result`、`duration_bucket`；不含提示词、回答或模型错误文本 |
| `export_completed` | Markdown 导出结束 | `export_kind`、`result`；不含导出路径或文件名 |

### 5.3 错误分类

业务代码只能上报固定的 `error_category`，例如：`configuration`、`authentication`、`authorization`、`network`、`rate_limited`、`source_unavailable`、`unsupported_content`、`download`、`media_decode`、`asr`、`ocr`、`llm_provider`、`storage`、`conflict`、`cancelled`、`internal`。

`fingerprint` 只可由预先定义的错误类型和代码位置生成，例如 `sha256("pipeline:asr:model_load")` 的短前缀。不得对原始异常文本、路径、URL 或堆栈直接哈希后上传，因为它们仍可能携带用户信息。

## 6. 本地存储、上传与保留

### 6.1 本地队列

- 独立文件：`data/telemetry.sqlite`；最大 10 MB 或 10,000 条，以先到者为准。
- 用户选择关闭后不再写入；选择“关闭并删除”时删除数据库、早期 NDJSON 暂存和 Keychain 中的随机安装 ID。
- 未上传事件最多保留 14 天；超过期限自动删除。上传确认后的事件立即删除。
- 写入、清理、上传均不得阻塞 UI、任务队列、转写、OCR 或退出流程。

### 6.2 上传策略

- 仅在用户同意、应用空闲且没有前台关键任务时执行。
- 首次上传至少延迟 30 分钟；之后每 12 小时至多一次。网络错误使用带随机抖动的指数退避，最长 7 天。
- 批次使用 idempotency key；服务端按 `event_id` 去重。HTTP 4xx 的 schema/权限错误丢弃并仅保留本地计数；5xx 与超时保留重试。
- 允许用户在设置页点击“立即发送”，但不可因此绕过字段检查或扩大批量大小。

### 6.3 服务端保留与访问

- 原始去标识事件默认保留 90 天；仅保留按日期、版本、平台和固定枚举维度聚合后的指标，最长 24 个月。
- 不建立个人档案，不向其他系统导出安装级明细，不把遥测与支持工单、支付或账号数据关联。
- 管理后台采用最小权限、单点登录/强认证和访问审计；仅产品、工程和安全职责人员可访问对应聚合层级。
- 数据存储地域、跨境传输与发布地区的告知/同意要求必须在正式发布前由法务或隐私负责人确认；本方案不构成合规结论。

## 7. 指标与看板

### 7.1 发布健康看板

- 匿名活跃安装量、版本采用率、启动成功率、P50/P95 启动时长。
- `app_fault`、`pipeline_failed` 的安装占比与事件率，按版本、组件和错误类别对比。
- 上传成功率、字段拒绝率和本地队列丢弃率；这些用于验证遥测本身不制造问题。

### 7.2 核心旅程漏斗

| 旅程 | 关键事件 | 要回答的问题 |
| --- | --- | --- |
| 内容导入 | `content_capture_started` → `content_capture_completed` → `task_enqueued` | 哪类来源导入失败或被重复内容阻断？ |
| 视频处理 | `task_enqueued` → 阶段事件 → `pipeline_completed/failed` | 下载、ASR、总结分别是多慢、哪里最常失败？ |
| 知识使用 | `workspace_view_opened` → `search_executed` / `qa_answer_completed` | 用户是否真的使用检索与问答，而非只做收藏？ |
| 本地沉淀 | `markdown_sync_completed` | Obsidian 同步是否可靠，冲突是否集中发生？ |
| 内容订阅 | `subscription_sync_completed` / `report_generation_completed` | 哪类自动来源和报告能力有稳定需求？ |

### 7.3 解释规则

- 所有采用率同时展示选择加入率，不能把“已同意遥测用户”的行为直接外推为全体用户。
- 默认只对达到最小样本量（建议 20 个不同安装）的聚合分组做产品决策，避免小样本噪声。
- 性能回归以同版本、同来源类别、同处理模式的 P50/P95 对比，不以单条任务判断。

## 8. 用户体验文案与交互

首次询问建议文案：

> 帮助改进 KnowledgeHub
>
> 如果你愿意，可匿名发送启动速度、功能使用和错误类别，帮助我们修复问题并改进体验。不会上传你的文章、视频、字幕、问答、文件路径、账号或密钥。你可随时在“设置 → 隐私与诊断”关闭并删除本地待发送数据。

按钮：`允许匿名使用数据`、`暂不发送`。不使用预选开关、倒计时、遮挡关闭按钮或因拒绝而降低功能可用性的设计。

设置页需要提供：

1. 总开关和当前状态；
2. 可读的“采集 / 不采集”摘要及隐私说明链接；
3. 上次上传状态、待发送数量、所用隐私说明版本；
4. `立即发送` 与 `关闭并删除本地数据` 两个明确动作，并对后者进行可恢复性说明；
5. 单独的“发送反馈”入口。反馈正文必须采用独立、明确的同意与脱敏流程，不能混入遥测事件。

## 9. 实施顺序

### Phase 0：发布前设计冻结

- 评审本方案、事件目录、字段白名单、服务端数据地域与隐私说明。
- 确定收集端域名与部署边界，建立开发/预发布/生产三套隔离环境。**待确认：**本仓库不会猜测或内置正式域名。
- 为每个事件指定产品负责人、代码所有者、用途、允许字段和删除日期。

### Phase 1：本地闭环（不上传）

- 已实现事件目录、枚举收敛、独立队列、设置页、非模态同意说明及默认禁用的低频上传器。
- 为启动、任务流水线、错误分类、下载、转写、AI、搜索、更新和 Obsidian 同步接入 20 个高价值事件。
- 已完成本地单元测试和“未知字段不得入队、未知枚举归为 other、隐私说明版本变化会丢弃旧队列”的回归测试。

### Phase 2：受控试点上传

- 仅对主动加入的内部测试者或 beta 渠道开启官方收集端。Cloudflare Worker 源码位于 `telemetry-worker/`，部署不得通过 GitHub Actions 自动执行。
- 建立版本健康、任务漏斗和遥测质量三个基础看板。
- 审核真实样本，验证无自由文本、无路径、无凭据，并观察队列/网络开销。

### Phase 3：正式发布与迭代

- 正式渠道保持默认关闭；监控选择加入率、崩溃率、上传失败率和用户反馈。
- 每月审查事件使用价值：连续 90 天未被使用或无法对应决策的问题字段/事件应删除。
- 新功能先补事件方案和隐私评审，再进入实现；不得事后从日志或数据库挖取内容行为。

### 9.1 GitHub 手动更新兼容性

- DMG 替换安装保留本机数据目录，因此会保留已同意的遥测设置；不会因更新而重复弹窗。
- `privacy_notice_version` 是同意边界。新增事件、字段、收集方、保留期或用途时必须升级该版本；新版本启动后清除旧待发送队列、停止记录，并重新显示非模态说明。
- 仅修正文案、前端布局或不改变字段/用途的发布，不升级该版本。
- 旧版本事件无法映射到当前 schema 时直接丢弃；绝不把旧自由文本或未知字段“兼容”后上传。
- 收集端 URL、Cloudflare 密钥、Analytics 查询令牌均不得进入 GitHub Release、DMG、设置页或本机内容数据库。

## 10. 验收与测试清单

- [ ] 网络离线、限流、4xx、5xx、应用强制退出和数据库占用时，主应用仍可启动、处理任务和正常退出。

## 11. 待确认决策

1. 发布地区与正式数据存储地域；这决定隐私说明与合规审查范围。
2. 收集端采用自建 API/数据库，还是经安全与数据处理评估后使用托管分析平台。
3. 是否在 beta 渠道采用“默认提示、用户选择”之外的更明确测试协议；正式版仍建议默认关闭。
4. 服务端聚合看板的访问角色与异常告警接收人。
5. 是否将用户主动提交的反馈做成独立系统；如做，需另立反馈附件、内容脱敏和响应流程，不能复用本方案的遥测许可。
