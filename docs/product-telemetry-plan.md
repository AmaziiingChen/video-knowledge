# KnowledgeHub 产品遥测与使用数据方案

版本：v1.2（默认开启试运行）
日期：2026-08-13
状态：新安装默认开启、首次非模态告知与持久退出偏好已实现；v2/v3 过渡收集器已手动部署并通过配置回读与 HTTP 烟测，Analytics Engine 双版本入库回读待完成

## 1. 决策摘要

KnowledgeHub 引入**隐私优先、字段固定、默认开启但可持久退出**的产品诊断，用于判断产品是否稳定、用户在哪些链路受阻，以及哪些功能值得持续投入。遥测不是内容同步：视频、字幕、文章正文、问答、Markdown、截图、Cookie、令牌和文件路径均不进入遥测系统。

第一期不接入第三方行为分析 SDK。新安装默认把严格枚举的事件写入独立、可删除的遥测队列，并在首次进入工作台时明确告知；应用启动至少 60 秒后才通过 HTTPS 批量发送到官方收集端。用户可以立即关闭，关闭会删除队列和随机安装 ID，只保留一位不含遥测数据的本机退出偏好，避免更新后重新开启。

当前代码已经实现固定事件目录、严格枚举、14 天/10,000 条本机队列上限、非模态说明、版本边界及低频批量上传循环。上传器仅接受源码白名单中的精确 HTTPS 主机，禁用代理和重定向，失败时保留队列并指数退避。同时接受严格一致 v2/v3 信封的受控试运行 Worker 已于 2026-08-13 手动部署到 `https://knowledgehub-telemetry-collector.knowledgehub4chen.workers.dev/v1/events`；配置回读及 404、400、413、v2 202、v3 202 远程烟测已通过，桌面端 v3 发布前仍须完成两个合成事件的 Analytics Engine 入库回读。

## 2. 目标、非目标与成功标准

### 2.1 目标

1. 量化启动、导入、处理、搜索、同步、更新与导出等已进入固定目录的产品检查点。
2. 以稳定的结果与阶段枚举定位可靠性问题，不上传原始报错或用户内容。
3. 识别功能采用率、漏斗流失和性能回归，为版本优先级提供证据。
4. 让用户随时知道是否在共享数据、将要共享什么，并能一键停止和清除。

### 2.2 非目标

- 不做广告、跨站追踪、用户画像、内容推荐画像或销售线索收集。
- 不记录页面键入、剪贴板、URL、搜索词、标题、文件名、公众号名称、账号标识、地理位置或设备硬件序列号。
- 不以遥测代替用户反馈、错误复现或安全日志。
- 不把遥测开关、首次告知或退出偏好做成隐藏控制；正式分发地区的合法基础与告知要求需独立复核。

### 2.3 第一阶段成功标准

- 发布后可以按版本、macOS 大版本和固定枚举观察任务完成率、到达阶段与失败阶段。
- 能发现某版本的任务失败率、阶段分布或核心功能使用结果出现明显变化；当前目录不采集崩溃和启动耗时，不能声称对应指标。
- 用户可在设置页查看采集说明、本地待发送数量，并可立即关闭和删除本地队列。
- 审计抽样确认：上报负载中不含正文、路径、URL、凭据、原始异常、用户输入或可逆个人标识。

## 3. 隐私与数据边界

### 3.1 控制模型

- **新安装默认开启。** 首次进入工作台显示非模态事实告知，并提供“知道了”“关闭并清除”“查看说明”三个动作；不阻塞工作台。
- 应用启动至少 60 秒后才进行首次上传检查，为立即关闭保留窗口。关闭后不创建可上传事件，只保留产品运行必需的本地日志，且不把这些日志转作遥测。
- 用户可在“设置 → 隐私与诊断”随时关闭。关闭立即停止上传、删除本地待发送事件与随机安装 ID，并持久保存不含身份或遥测的一位退出偏好。
- 更新说明、扩大字段、新增收集方或改变用途时，须提升说明版本、清空旧版本待发队列并重新告知；不得把实质变化当作文案修订。

### 3.2 允许字段

| 分类 | 允许的数据 | 约束 |
| --- | --- | --- |
| 版本与运行环境 | app 版本、macOS 主版本、CPU 架构 | 不传构建渠道、设备名、用户名、主机名、精确系统补丁号 |
| 产品操作 | 固定事件名、工作区、结果、处理阶段、处理模式 | 均为预定义枚举；不得出现标题、URL 或用户自定义名称 |
| 性能 | 当前目录不上传连续性能数值 | 不传原始耗时、文件大小、队列长度或内存数据；性能测量另行设计 |
| 故障 | 固定 `result=failed` 与固定阶段桶 | 不采集错误类别、指纹、原始异常、堆栈、HTTP 响应、请求体和日志行 |
| 隐私控制 | 用户主动重新开启状态 | 默认初始化不伪造同意事件；关闭删除遥测库，仅保留本机退出偏好 |

### 3.3 明确禁止字段

- 内容：视频/音频、图片、OCR 文本、字幕、文章、报告、Markdown、问答、提示词、搜索词和剪贴板文本。
- 身份与凭据：姓名、邮箱、手机号、IP 地址、设备标识符、Cookie、Token、API Key、登录态、微信/Telegram/Obsidian 账号。
- 可定位信息：文件路径、文件名、域名、完整 URL、外部来源 ID、网络 SSID、精确位置、时区以外的定位信息。
- 原始诊断：原始 error message、堆栈、HTTP headers/body、进程命令行、截图、日志片段。

## 4. 端到端架构

```text
Vue / Electron / FastAPI 产生预定义事件
                 ↓
         本地字段白名单与脱敏器
                 ↓
   独立 telemetry.sqlite 队列（可查看、可删除）
                 ↓  默认开启、可退出、低频批量、HTTPS
 Cloudflare Worker（严格 schema；不接收自由文本）
                 ↓
 Workers Analytics Engine（固定槽位；最长保留 3 个月）
```

### 4.1 客户端组件

1. **事件目录（event registry）**：代码中唯一允许出现的事件名、字段、枚举和版本。未知事件或未知字段直接拒绝写入。
2. **本地队列**：单独使用 `data/telemetry.sqlite`，不与 `app.db`、内容库或任务数据库混写；最多保留 10,000 条或 14 天，超过时先丢弃最早事件。
3. **上传器**：由后端低优先级线程运行。启动后先等待 60 秒，健康状态下每 12 小时检查一次；单次最多 100 条，失败后从 5 分钟起有界退避，不影响视频、ASR、OCR 或 AI 任务。明确退出时队列为空且不创建网络请求。
4. **设置与审计 UI**：首次显示默认开启告知；设置页展示总开关、事件说明和本机待发送数量。关闭开关会删除独立遥测数据库与随机安装 ID，并保留退出偏好。

### 4.2 建议的项目落点

| 位置 | 职责 |
| --- | --- |
| `backend/services/telemetry.py` | 字段校验、SQLite 队列、保留清理、批次构造与成功确认删除 |
| `backend/services/telemetry_uploader.py` | 精确目的地校验、低频上传、失败退避和应用生命周期 |
| `backend/routers/telemetry.py` | 仅本机可访问的设置、状态、事件写入、清除接口 |
| `backend/services/application_lifecycle.py` | 随桌面后端生命周期启动/停止上传器 |
| `backend/main.py` | 注册本机遥测路由并继承桌面 API 能力边界 |
| `frontend/src/features/desktop/useDesktopActionController.js` | 通过受保护的本机 API 记录前端事件；渲染器不直接访问 Cloudflare |
| `frontend/src/components/SettingsDialog.vue` | “隐私与诊断”设置页；沿用既有圆角 token 与设置页结构 |
| `tests/test_telemetry*.py` 与前端单元测试 | 字段白名单、关闭不写入、删除、上传重试、敏感字段回归测试 |

### 4.3 网络与服务端边界

- 客户端只允许连接源码中声明的精确官方 HTTPS 主机；当前仅允许 `knowledgehub-telemetry-collector.knowledgehub4chen.workers.dev`。同账号其他 Worker、预览 URL、端口、查询参数、重定向和环境覆盖均被拒绝。
- 上传接口只接受严格 JSON schema，不接受自由文本字段、附件或任意嵌套对象；服务端也必须再次执行字段白名单验证。
- 不把用户配置的代理、第三方 AI Key 或内容来源会话用于遥测认证。
- Worker 对请求体实行 256 KiB 硬上限，并使用不依赖 IP 的两级速率限制：静态全局路由键与按月轮换的 HMAC 安装键。`workers.dev` 是公开端点，限流按 Cloudflare PoP 最终一致，只用于减损，不能作为精确配额或身份认证。
- Workers 持久调用日志显式关闭；Analytics Engine 只写固定 15 个字符串槽、3 个数值槽与按月轮换的 HMAC 采样索引。原始安装 UUID、请求头、安装限流键和 properties JSON 不进入数据集。
- 此数据只能作为可能被伪造、重复或抽样的 beta 诊断信号，不用于计费、安全、身份或个体判断。

## 5. 事件契约

### 5.1 通用事件格式

```json
{
  "schema_version": 1,
  "privacy_notice_version": "2026-08-telemetry-v3",
  "installation_id": "本机随机 UUID，仅用于本次批次的内存 HMAC",
  "events": [{
    "schema_version": 1,
    "privacy_notice_version": "2026-08-telemetry-v3",
    "event_id": "随机 UUID",
    "event_name": "task_finished",
    "occurred_at": "2026-08-13T09:20:00Z",
    "app_version": "0.1.1",
    "platform": "macos",
    "os_major": 15,
    "architecture": "arm64",
    "properties": {"result": "succeeded", "stage": "summary"}
  }]
}
```

`installation_id` 必须在默认初始化或用户重新开启时随机生成，不得由硬件、账号、网络或文件数据推导。它随批次通过 TLS 到达 Worker，仅在内存中用于派生用途隔离、按月轮换的 HMAC 安装限流键与 Analytics Engine 采样索引；v3 还按说明版本隔离。原始值不写入分析库；用户关闭后销毁，重新开启生成新值。

所有 `properties` 都必须与对应事件的固定字段集合完全一致，值只能来自枚举。日期一律 UTC；结果数量只使用分桶值，例如 `0`、`1_5`、`21_100`、`101_plus`。

### 5.2 首个封闭测试版事件目录（严格 17 个）

| 事件 | 触发时机 | 允许属性 |
| --- | --- | --- |
| `app_started` | 已选择加入后的应用启动 | 无 |
| `workspace_opened` | 工作区切换/首次打开 | `view`（固定枚举） |
| `import_started` | 用户提交链接导入 | `input_kind`（当前仅 `link`） |
| `import_completed` | 链接已被本机接受并创建处理请求 | `result`（当前仅 `accepted`） |
| `task_enqueued` | 建立后台处理任务 | `processing_mode`（`full` / `transcript`） |
| `pipeline_stage_reached` | 任务首次到达一个稳定阶段桶 | `stage`（固定阶段名）；不表示阶段成功完成 |
| `pipeline_stage_failed` | 任务失败时记录其最终阶段 | `stage`；不含错误文本 |
| `task_finished` | 任务最终成功或失败 | `result`、`stage`；不含错误文本 |
| `task_control_used` | 用户重试、暂停、恢复或取消任务 | `action`（固定枚举） |
| `paddle_ocr_completed` | 一次 Paddle OCR 云端结果返回 | `result`（`succeeded` / `empty` / `failed`） |
| `obsidian_sync_completed` | Obsidian 写入或冲突检测完成 | `result`（`succeeded` / `conflict`） |
| `search_completed` | 本地搜索完成 | `result_count_bucket`；不含搜索词 |
| `clipboard_listener_changed` | 剪贴板监听启用或停止 | `state`（`enabled` / `disabled`） |
| `update_check_completed` | 手动更新检查结束 | `result`（`available` / `up_to_date` / `disabled` / `unavailable`） |
| `telemetry_consent_changed` | 用户关闭后主动重新开启遥测 | `state`（当前仅 `enabled`；默认初始化不产生该事件） |
| `update_download_page_opened` | 用户确认打开手动更新下载页 | 无 |
| `export_completed` | Markdown 导出结束 | `export_kind`、`result`；不含导出路径或文件名 |

### 5.3 错误边界

当前封闭目录不上传 `error_category`、错误指纹或可否重试等字段。失败仅以对应事件的 `result=failed` 和固定 `stage` 桶表示。未来若确需增加错误类别，必须先扩展固定 schema、升级隐私说明版本并重新告知；不得对原始异常、路径、URL 或堆栈做哈希后上传。

## 6. 本地存储、上传与保留

### 6.1 本地队列

- 独立文件：`data/telemetry.sqlite`；最多 10,000 条。
- 用户选择关闭后不再写入；关闭时删除整个遥测数据库，其中包括待发送事件和随机安装 ID。单独的 `telemetry-preference` 文件只保存 `explicit_disabled`，用于跨重启与手动更新尊重退出选择。
- 未上传事件最多保留 14 天；超过期限自动删除。上传确认后的事件立即删除。
- 写入、清理、上传均不得阻塞 UI、任务队列、转写、OCR 或退出流程。

### 6.2 上传策略

- 默认开启时在应用启动 60 秒后首次执行；之后健康或空队列状态每 12 小时检查一次。明确退出时不组批、不创建请求。
- 网络或服务错误从 5 分钟开始指数退避，最长不超过 12 小时；失败与 4xx 均保留本地批次，不阻塞产品功能。
- 每批最多 100 条。Analytics Engine 写入是 at-least-once；响应丢失后重试可能产生重复事件，分析查询须按 `event_id` 去重并使用 `_sample_interval` 汇总。当前不声称服务端幂等。

### 6.3 服务端保留与访问

- Cloudflare Workers Analytics Engine 对这些固定去标识事件保留最多 3 个月；本阶段不另建长期聚合库。
- 不建立个人档案，不向其他系统导出安装级明细，不把遥测与支持工单、支付或账号数据关联。
- 管理后台采用最小权限、单点登录/强认证和访问审计；仅产品、工程和安全职责人员可访问对应聚合层级。
- 数据存储地域、跨境传输与发布地区的告知/同意要求必须在正式发布前由法务或隐私负责人确认；本方案不构成合规结论。

## 7. 指标与看板

### 7.1 当前可建立的 beta 看板

- 去标识月活跃安装量、版本采用率与 `app_started` 事件量；`app_started` 只表示后端已启动，不代表完整启动成功率或启动耗时。
- `task_enqueued` 到 `task_finished` 的结果分布，按版本、处理模式与固定失败阶段对比。
- 工作区打开、搜索结果分桶、更新检查、剪贴板监听和 Markdown 导出的采用情况。

### 7.2 核心旅程漏斗

| 旅程 | 关键事件 | 要回答的问题 |
| --- | --- | --- |
| 内容导入 | `import_started` → `import_completed` → `task_enqueued` | 链接提交是否进入既有任务队列？当前不区分来源平台。 |
| 处理任务 | `task_enqueued` → `pipeline_stage_reached/failed` → `task_finished` | 任务到达了哪些稳定阶段桶，最终结果如何，失败集中在哪一阶段？ |
| 搜索使用 | `workspace_opened` → `search_completed` | 哪些工作区被打开，本地搜索结果数量分布如何？不含搜索词。 |
| 本地沉淀 | `obsidian_sync_completed` / `export_completed` | Markdown 写入与导出是否成功或发生冲突？ |

### 7.3 解释规则

- 所有采用率同时展示遥测开启率；退出用户不在样本内，不能把观察到的行为直接外推为全体用户。
- 默认只对达到最小样本量（建议 20 个不同安装）的聚合分组做产品决策，避免小样本噪声。
- 当前目录不能回答耗时回归；若后续增加性能桶，必须先升级隐私说明版本并重新告知，且不得从分桶反推伪精确 P50/P95。

## 8. 用户体验文案与交互

首次事实告知文案：

> 去标识使用诊断已开启
>
> KnowledgeHub 默认通过 Cloudflare 低频发送 17 个固定检查点。不会上传文章、视频、字幕、问答、搜索词、文件路径、账号、密钥或错误原文；数据最多保留 3 个月。你可立即关闭，且不影响任何产品功能。

按钮：`知道了`、`关闭并清除`、`查看说明`。不使用倒计时、遮挡关闭按钮或因退出而降低功能可用性的设计。

当前设置页提供：

1. 总开关和当前状态；
2. 可读的“采集 / 不采集”摘要及隐私说明链接；
3. 本机待发送数量；
4. 关闭并删除本机待发送数据的明确说明。

手动立即发送、上次上传状态和独立反馈入口属于后续可用性事项；反馈正文若实现，必须采用独立、明确的同意与脱敏流程，不能混入遥测事件。

## 9. 实施顺序

### Phase 0：发布前设计冻结

- 评审本方案、事件目录、字段白名单、服务端数据地域与隐私说明。
- 已确认 beta 收集端为免费 `workers.dev` 精确地址；在关键规模或正式 SLA 前再评估自有域名和环境隔离。
- 为每个事件指定产品负责人、代码所有者、用途、允许字段和删除日期。

### Phase 1：本地闭环（不上传）

- 已实现事件目录、枚举收敛、独立队列、设置页、非模态默认开启说明及持久退出的低频上传器。
- 为启动、任务流水线到达/失败/最终结果、搜索、更新、导出和 Obsidian 同步接入 17 个高价值事件。
- 已完成本地单元测试和“未知字段不得入队、未知枚举归为 other、隐私说明版本变化会丢弃旧队列”的回归测试。

### Phase 2：受控试点上传

- 同时接受 v2/v3 的过渡 Worker 已于 2026-08-13 手动部署，100% 流量配置、既有 HMAC secret、Analytics Engine 与两项限流绑定均已回读确认；404、400、413、v2 202 与 v3 202 远程烟测通过。桌面端 v3 发布前仍须回读两个合成事件，确认说明版本及 HMAC 索引隔离。普通重部署不得轮换密钥或限流 namespace；Cloudflare Worker 源码位于 `telemetry-worker/`，部署不得通过 GitHub Actions 自动执行。
- 建立版本健康、任务漏斗和遥测质量三个基础看板。
- 审核真实样本，验证无自由文本、无路径、无凭据，并观察队列/网络开销。

### Phase 3：正式发布与迭代

- 正式渠道的默认值与合法基础必须按发布地区完成隐私/法律复核；监控版本采用、任务结果、阶段分布和用户反馈。崩溃率与上传失败率不在当前目录内，需独立设计后才能采集。
- 每月审查事件使用价值：连续 90 天未被使用或无法对应决策的问题字段/事件应删除。
- 新功能先补事件方案和隐私评审，再进入实现；不得事后从日志或数据库挖取内容行为。

### 9.1 GitHub 手动更新兼容性

- DMG 替换安装保留本机数据目录，因此会保留明确退出或主动重新开启的设置；不会因普通更新重新开启已退出用户。
- `privacy_notice_version` 是事实告知边界。新增事件、字段、收集方、保留期或用途时必须升级该版本；新版本启动后清除旧待发送队列、轮换随机安装 ID，并重新显示非模态说明。
- 仅修正文案、前端布局或不改变字段/用途的发布，不升级该版本。
- 旧版本事件无法映射到当前 schema 时直接丢弃；绝不把旧自由文本或未知字段“兼容”后上传。
- 收集端 URL 是公开网络配置，可进入受审源码和 DMG。Cloudflare HMAC 密钥与 Analytics 查询令牌不得进入 GitHub、Release、DMG、设置页或本机内容数据库。
